## 2. 背景

<!-- なぜこのアプリを作るのか、現在どのような不便があるのかを利用者視点で記述する。 -->

- 自分でニュースを開いて見たいニュースを選んで、それを頭に入れるのが面倒
- 朝一に重要なニュースをいくつか見ることで世間の大体の流れを把握する

## 3. 目的

<!-- アプリによって実現したい状態を記述する。実装技術の説明は必要最小限にする。 -->

- 個人が国内および海外の主要な経済ニュースを短時間で確認できるようにする。
- 国内記事は日本語、海外記事は英語で確認できるようにする。
- Jetpack Composeを使用したAndroidアプリ開発を、要件定義からテストまで通して学習する。


## 4. 機能要件

<!-- この段階では「何ができるか」を記述し、ComposeやRoomなどの実装方法は設計書に記述する。 -->

| ID     | 要件                        | 優先度    |
|--------|---------------------------|--------|
| FR-001 | 国内ニュースを取得できること            | Must   |
| FR-002 | 海外ニュースを取得できること            | Must   |
| FR-003 | 取得したニュースを国内と海外に分けて表示できること | Must   |
| FR-004 | 記事のタイトル、配信元、公開日時を表示できること  | Must   |
| FR-005 | 記事を選択して配信元の記事を開けること        | Must   |
| FR-006 | ニュース取得を原則1日1回に制限できること     | Must   |
| FR-007 | 取得失敗時に再試行できること             | Must   |
| FR-008 | 記事の既読状態を保持できること           | Could  |

### 4.1 取得件数

<!-- 「1日分」を検証可能な数値または条件で定義する。 -->

- 国内ニュース：最大5件
- 海外ニュース：最大5件
- 取得対象：過去24時間に公開されたビジネスカテゴリの主要記事
- 国内記事：日本語かつ日本向けの記事
- 海外記事：英語の記事
- 画像は取得・表示しない

### 4.2 更新契機

- 定期更新：朝に1回
- 手動更新：取得失敗時の再試行として提供する
- 初回起動時：当日の保存済み記事がない場合に取得する
- 当日の取得済み判定：端末のローカル日付を基準に判定する

## 5. 外部サービスと制約

### 5.1 ニュースAPI

- ニュース取得にはGNews APIを使用する。
- 国内は日本語記事、海外は英語記事を対象とする。
- 国内ニュースと海外ニュースは別々に取得する。
- 国内・海外ともにビジネスカテゴリを使用する。
- 無料プランの範囲で利用する。
- APIの利用条件、取得件数、遅延時間は変更される可能性があるため、実装開始前に再確認する。

### 5.2 APIキー

- APIキーをGitリポジトリへコミットしない。
- Androidアプリへ組み込んだAPIキーは完全には秘匿できないことを制約として扱う。
- 一般公開する場合は、外部サービスの利用条件とAPIキーの管理方法を再検討する。
